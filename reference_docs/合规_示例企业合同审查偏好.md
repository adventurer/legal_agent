# 示例企业合同审查偏好

> 示例资料，仅用于知识库导入、检索和审查流程演示。不是任何真实企业已批准的制度，也不是法律意见。正式使用前，请由企业法务和业务负责人确认并替换为本企业口径。

## 付款与交付

- 合同应分别写清交付内容、交付地点、计划日期、验收标准、验收期限和不合格时的处理方式。
- 付款条件应明确付款节点、计算起点、所需单据及开票要求；避免仅使用“尽快付款”“验收后付款”等缺少操作细节的表述。
- 分阶段付款的，应将每期金额或比例与可核验的交付、验收或里程碑对应。
- 修改建议应尊重合同已经明确的日期、金额和条件，不得把现有约定误写为缺失。

## 违约责任

- 核对违约事件、通知和补救期限、责任计算方式、责任上限及损失范围是否彼此衔接。
- 对单方免除主要责任、责任上限过低或责任范围不对称的内容，提示业务负责人评估交易风险并确认可接受边界。
- 对逾期付款、迟延交付、质量不合格和数据安全事件，分别核对是否有可执行的处理流程；不要把不同违约情形合并成无法操作的概括条款。
- 责任金额、比例和上限属于商务谈判参数，应由业务负责人确认，不在本示例中设定固定数值。

## 争议解决

- 核对争议解决方式是否明确且前后一致；选择仲裁时，记录双方约定的仲裁机构、仲裁地、语言和仲裁员产生方式。
- 发现机构名称、地点或选任方式不完整时，作为待确认事项提出，不要自行补写为双方已经同意的安排。
- 对争议解决条款的法律效力判断，必须另行检索适用法律和合同原文；本企业偏好不能替代法律依据。

## 保密与数据

- 核对保密信息范围、例外情形、允许接触人员、使用目的、保护措施、期限以及返还或删除流程。
- 涉及个人信息、重要业务数据或第三方资料时，要求业务负责人确认数据类别、处理目的、访问权限、保存期限和对外提供条件。
- 对保密信息与商业秘密的范围有疑问时，分别描述合同约定和待核实事实；不要仅凭“保密”字样认定某项信息当然构成商业秘密。

## 使用边界

- 本文件提供内部审查清单和谈判提示，不是法律条文、强制性规定或已验证的公司政策。
- 没有企业书面确认的期限、金额、责任上限和审批权限，应标注为待确认，不得当作既定公司红线。
