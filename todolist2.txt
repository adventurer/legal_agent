================================================================================
           Legal Agent Lab - 第二阶段演进与系统深化路线图 (Roadmap)
================================================================================

当前系统已完成第一阶段闭环：打通多模态文档解析/OCR、ReAct 智能体循环、法规与
自编法典检索、FastAPI SSE 流式网关以及 Streamlit 双栏可视化工作台。

进入第二阶段，系统聚焦于【业务深度落地、审查精准度提升与工程加固】，主要规划
以下四个核心维度的演进方向：

--------------------------------------------------------------------------------
一、审查粒度升级：从“全文笼统审”到“条款级穿透审 (Map-Reduce)”
--------------------------------------------------------------------------------

解决痛点：
面对几十页或上百条的长合同，一次性送入模型容易遇到 Token 上限、注意力稀释、
关键免责条款被遗漏等问题。

演进方案：
1. Map-Reduce / 逐条审查流水线
   - Map 阶段：利用已有的 doc_loader.py 条款切分能力，对每个独立条款进行并行/异步审查；
   - 单条聚焦：针对单个条款（如违约责任、付款条件）精准触发工具检索，单条思考更聚焦，
     杜绝上下文过长导致的幻觉；
   - Reduce 阶段：最后由汇总 Agent 进行全同审查，专职识别“跨条款矛盾”
     （例如第二条约定付款后交货，第六条却约定交货后付款）。

2. 审查立场选择器 (买方 / 卖方 / 中立)
   - 在前端界面提供审查立场切换开关；
   - 动态调整判定尺度：同一条款（如“逾期违约金每日千分之五”），若站在买方（受票方）
     属于合理甚至偏优条款，若站在卖方（交付方）则是必须坚决下调的重大违约红线。

--------------------------------------------------------------------------------
二、成果导出与闭环：从“只看不动”到“Word 批注修改 (Redline)”
--------------------------------------------------------------------------------

解决痛点：
法务与业务人员在日常流转中很少直接使用网页报告，最终交付物必须是能够直接发给
业务部门或对方律师审阅的带痕迹合同。

演进方案：
1. 自动生成带“批注 (Comments)”与“修订 (Track Changes)”的 .docx
   - 使用 python-docx 扩展库，将 Agent 提炼出的 suggested_revision（建议修改）
     与 issue（风险点）以 Word 原生批注或划线替换形式直接回写到原始文档中；
   - 用户在 Streamlit 点击“一键导出批注版合同”，即可直接在 Microsoft Word / WPS
     中逐条查看并点击“接受修订”。

2. 自动生成正式法务意见书
   - 结构化导出带有公司抬头、审核时间戳、风险等级统计图表的《合同法律合规审查意见书》
     （支持导出 Markdown 或 PDF）。

--------------------------------------------------------------------------------
三、检索能力进化：从“关键词匹配”到“混合检索 (Hybrid RAG)”
--------------------------------------------------------------------------------

解决痛点：
目前知识库基于简单正则与关键词搜索，面对长尾法律表述或同义替换时，容易出现
法条查不全或语义偏差。

演进方案：
1. 混合检索架构 (Dense + Sparse)
   - BM25 (精准稀疏检索)：精准匹配法条编号与固定术语（如“民法典第585条”、“仲裁法第16条”）；
   - 本地轻量向量检索 (语义稠密匹配)：集成轻量向量库（如 ChromaDB / FAISS）与
     本地中文嵌入模型（如 bge-small-zh-v1.5），解决“表述不同但语义一致”的召回问题
     （如合同中写“滞纳金/违约扣款”，仍能精准召回“违约金”相关司法解释）。

2. 法规条文层级关联
   - 命中具体法条时，自动关联最高人民法院相关司法解释条文及典型指导案例。

--------------------------------------------------------------------------------
四、企业自编法典管理台 (管理端增强与记忆飞轮)
--------------------------------------------------------------------------------

解决痛点：
目前业务红线与偏好规则需手动写入 SQLite 或固化在脚本中，缺乏法务人员自主运营能力。

演进方案：
1. 可视化规则管理大厅 (CRUD)
   - 在 UI 增加独立的法典配置页面，允许法务主管直接在网页上新增、修改或停用公司红线
     （如“对外付款账期不得短于60天”、“严禁约定对方单方管辖”）。

2. 历史审查反馈与自我进化飞轮
   - 提供“采纳 / 驳回”建议的反馈闭环；
   - 当法务人员采纳某条优秀修改建议时，可“一键沉淀为企业模板规则”，自动写入 SQLite，
     使系统随着实际使用越审越准。
